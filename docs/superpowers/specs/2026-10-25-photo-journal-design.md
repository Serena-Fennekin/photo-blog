# 个人摄影日志网站设计规格

- 日期：2026-10-25
- 状态：已确认
- 视觉原型：`prototype-photo-journal/`
- 选定方向：B「时间章节」

## 1. 产品定位

这是一个以照片为主体的个人摄影日志，而不是商业摄影作品集或长篇博客。网站面向普通摄影爱好者、朋友和家人，全部已发布内容公开浏览。

核心体验包括：

1. 以时间、地点、组图与短句构成首页章节，让访客感受到持续记录的叙事。
2. 通过独立的艺术化文字入口进入摄影集。
3. 在摄影集中快速浏览全部照片，并在灯箱中查看照片细节、EXIF 与所属故事。
4. 通过低维护的后台完成批量上传、整理和发布。

文章不是独立内容类型。文字作为摄影记录的组成部分，只需要标题、地点和几句随笔，并通过排版形成艺术感。

## 2. MVP 范围

### 包含

- 首页时间章节
- 首页首屏封面设置
- 摄影集瀑布流与顶部分类筛选
- 照片灯箱、同组浏览、EXIF 与浏览量
- 组图记录详情
- 三态主题切换
- 单管理员后台
- 组图批量上传、排序、封面、草稿、预览、发布与撤回
- OSS 原图私有存储、展示图处理与 CDN 分发
- 24 小时去重浏览量
- SQLite 备份与基本运维能力

### 暂不包含

- 公开原图下载
- 用户注册、评论、点赞与收藏
- 多管理员或复杂角色权限
- 独立长文章系统
- 付费内容、电商或预约功能
- 人脸识别、自动打标和 AI 修图
- 多语言

## 3. 信息架构

### 公开页面

- `/`：首页
- `/gallery`：摄影集
- `/stories/:slug`：组图记录详情
- `/about`：关于我与联系方式

### 管理页面

- `/admin/login`：管理员登录
- `/admin`：内容概览
- `/admin/stories/new`：创建组图记录
- `/admin/stories/:id`：编辑组图记录
- `/admin/categories`：分类管理
- `/admin/settings`：封面、主题相关默认值及站点设置

管理路由不出现在公开导航中，并禁止搜索引擎索引。

## 4. 前台体验

### 4.1 全局导航

桌面端顶部常驻品牌、首页、摄影集、关于我和主题控件。移动端缩减为品牌、菜单与主题控件。

主题控件有三个明确选项：

- 跟随系统（默认）
- 深色
- 浅色

选择保存在浏览器本地。跟随系统模式监听系统主题变化并实时响应。首次加载前在文档头部尽早应用主题，避免页面闪烁。

### 4.2 首页

首页采用 B「时间章节」：

1. 首屏使用一张代表照片、摄影者名称与短句建立情绪。
2. 首屏下方按时间排列已发布组图记录。每个章节展示日期、手动地点、标题、短随笔、封面和少量组内照片。
3. 页面中段使用一段独立、留白充足的文字作为摄影集入口。
4. 页面末段提供关于我或联系方式入口。

首屏封面支持两种后台模式：

- 手动指定：默认模式，由管理员选择一张已上传照片。
- 跟随最新记录：自动使用最新已发布记录的封面。

自动模式没有可用照片时，继续使用上一次有效封面，避免空白首屏。

### 4.3 摄影集

摄影集顶部保留分类筛选。默认分类为“全部”，管理员可以新增、改名、排序和停用分类。

所有记录中的照片直接混排进响应式瀑布流，不先展示组图卡片。每张图片保留原始宽高比，加载时预留尺寸，避免布局跳动。

筛选切换保留轻量过渡；URL 查询参数记录当前分类，便于刷新、分享和返回。

### 4.4 照片灯箱

点击瀑布流照片打开沉浸式灯箱：

- 展示适配屏幕尺寸的大图
- 支持键盘、按钮和触摸手势切换同组照片
- 展示照片说明、所属记录和进入记录详情的入口
- 展示清洗后的 EXIF
- 展示累计浏览量
- 支持关闭、ESC 和浏览器返回
- 打开时锁定背景滚动，关闭后恢复原位置与焦点

公开 EXIF 只包括：相机、镜头、焦距、光圈、快门、ISO 和拍摄日期。GPS 精确坐标、设备序列号等敏感元数据不进入公开数据。地点只能在后台手动填写城市或区域。

### 4.5 组图记录详情

记录详情维持照片优先：标题、日期、地点和短随笔之后，按管理员设置的顺序展示整组照片。点击任意照片进入该组灯箱。

### 4.6 动效与无障碍

- 使用 GSAP 实现首屏进入、章节显现、图片轻微视差和摄影集入口过渡。
- 不以动画阻塞导航或图片交互。
- 移动端减少固定定位和视差强度。
- 系统启用 `prefers-reduced-motion` 时关闭非必要动画。
- 所有交互支持键盘，保留明显焦点状态。
- 图片提供后台可填写的替代文本；装饰图片使用空替代文本。
- 深浅主题均满足正文与控件的基本对比度要求。

## 5. 后台体验

### 5.1 权限

MVP 只有一个管理员账号，不开放注册。登录使用用户名和强密码，服务端 Session 写入安全 Cookie。

### 5.2 组图发布流程

1. 创建记录，填写标题、拍摄日期、地点、分类和简短随笔。
2. 一次拖入多张照片。
3. 浏览器取得短时上传凭证，将原图直接上传至私有 OSS，不经过 ECS 应用进程。
4. 上传完成后，服务端读取 OSS 图片信息，按白名单保存 EXIF，并触发展示图生成。
5. 管理员拖拽照片排序，指定一张记录封面，按需填写单张说明与替代文本。
6. 预览首页章节、记录详情与摄影集表现。
7. 保存草稿或发布；已发布记录可以编辑、隐藏或撤回。

关闭页面后再次进入草稿，应能看到已完成上传与处理状态。单张处理失败不影响其余照片，后台提供明确的失败原因与重试按钮。

### 5.3 删除策略

删除已发布记录前要求二次确认。默认先软删除数据库记录并隐藏前台内容；关联 OSS 文件进入延迟清理队列，保留一段恢复窗口，避免误删原图。

## 6. 技术架构

### 6.1 总体方案

采用单仓库的 Nuxt + Vue + TypeScript 应用：

- 服务端渲染公开页面，改善首屏和搜索引擎可读性。
- 客户端增强主题、瀑布流、灯箱和动画。
- 同一应用提供管理后台与轻量 API。
- Caddy 负责 HTTPS、反向代理和安全响应头。
- SQLite 保存业务数据。
- 阿里云 OSS（杭州）保存图片，CDN 分发展示图。

```text
访客 / 管理员浏览器
          │
          ▼
       Caddy
          │
          ▼
 Nuxt 应用（页面 + API）──── SQLite
          │
          ├── 短时凭证 ── 浏览器直传私有 OSS
          │
          └── 图片信息 / 处理任务 ── OSS 展示图 ── CDN
```

这套架构让 ECS 不承担公开图片流量，也不在应用内同步压缩大图，适合 2 核 2G 服务器。

### 6.2 前端

- Nuxt、Vue、TypeScript
- GSAP + ScrollTrigger 负责经过约束的滚动动效
- 瀑布流组件必须保持稳定顺序、支持响应式列数和图片尺寸占位
- 灯箱按需加载，避免进入首页时加载全部代码
- 图片组件生成 `srcset` 与 `sizes`，使用懒加载和渐进占位
- 前台公开数据通过服务端渲染或缓存 API 获取

### 6.3 后端

API 职责包括：

- 管理员登录、登出与 Session 校验
- 记录、照片、分类和设置的增删改查
- 生成短时 OSS 上传凭证
- 验证上传完成并读取图片信息
- 触发和跟踪展示图处理状态
- 记录去重浏览量
- 提供公开内容查询

长耗时操作不得阻塞 HTTP 请求。图片处理状态通过轻量任务表管理，由单进程后台执行器顺序消费；真正的缩放和格式转换交给 OSS 图片处理。

### 6.4 数据库

初期使用 SQLite WAL 模式。主要实体：

- `admins`：管理员凭据
- `sessions`：登录会话
- `stories`：组图记录、状态、发布时间、封面照片
- `photos`：OSS 对象键、尺寸、顺序、说明、替代文本、EXIF 与处理状态
- `categories`：分类与排序
- `story_categories`：记录与分类关系
- `settings`：首页封面模式、手选照片和站点配置
- `photo_view_totals`：照片累计浏览量
- `photo_view_dedup`：24 小时去重键及过期时间
- `jobs`：图片处理与延迟清理任务

数据库写操作使用事务。SQLite 文件放在持久卷，每天生成一致性备份并上传私有 OSS，保留多代备份。

当写入并发或内容规模超过单机边界时，可将数据层迁移至 PostgreSQL；业务模型不依赖 SQLite 特有能力。

## 7. 图片与 OSS 设计

### 7.1 对象分层

- 私有原图：永久母版，不对公网开放。
- 展示图：从原图生成，清除敏感元数据，提供多个尺寸和合适格式。
- CDN：只承载展示图路径，原图路径不进入公开响应。

建议以不可变对象键保存展示图，例如包含照片 ID、内容散列、宽度和格式。更换图片会产生新 URL，从而可以使用长期缓存，不需要批量刷新 CDN。

### 7.2 展示尺寸

首版至少提供缩略、中等、大图三个宽度档，并为常用浏览器提供 WebP；JPEG 作为兼容回退。是否增加 AVIF 由实际编码成本和浏览器覆盖率决定。

前端永远根据容器与设备像素密度选择合适尺寸，不在瀑布流加载灯箱级大图。

### 7.3 上传安全

- 上传凭证生命周期短，只允许指定对象前缀、文件类型和大小。
- 服务端不信任浏览器提交的 MIME 类型，上传完成后重新验证文件信息。
- 限制单文件大小、单批数量和管理员上传频率。
- 后台显示上传与处理两个独立进度。

## 8. 浏览量设计

灯箱中的照片真正进入可见状态后，前端发送一次计数请求。只预加载图片不计数。

服务端为浏览器生成匿名访客标识，结合照片 ID 和 24 小时时间窗计算不可逆去重键。同一访客、同一照片在 24 小时内只增加一次累计值。

计数接口要求：

- 原子写入去重记录与累计值
- 接口级速率限制
- 不保存原始 IP
- 定期删除过期去重行，累计值长期保留
- 计数失败不能阻断看图

浏览量是近似指标，不承诺防住清 Cookie 或分布式恶意刷量；如上线后出现攻击，再在 CDN/WAF 层增加挑战与更严格限速。

## 9. 缓存与性能

- 展示图使用长期不可变缓存，CDN 为主要传输路径。
- 公开内容 API 使用 ETag 或短时缓存；发布、撤回和设置变更时主动失效应用缓存。
- 首页只预加载首屏封面，后续照片懒加载。
- 摄影集分页或游标加载，避免一次返回全部照片。
- 灯箱只预取当前照片前后各一张。
- 字体进行子集化或选择可靠的系统字体回退，避免字体阻塞首屏。

## 10. 安全

- 密码使用 Argon2id 哈希。
- Session Cookie 设置 `HttpOnly`、`Secure` 和合适的 `SameSite`。
- 所有后台写操作校验 CSRF 或同源请求凭证。
- 登录接口、上传凭证与计数接口分别限速。
- Caddy 配置 TLS、安全响应头和请求体上限。
- 管理页面与 API 做服务端鉴权，不能只依赖前端隐藏。
- 展示文本进行转义或可信格式白名单处理。
- OSS 密钥只存在服务端环境变量中，不进入仓库或浏览器。

## 11. 异常与恢复

- OSS 或图片处理暂时不可用：记录保留草稿，后台展示失败状态并可重试。
- 展示图尚未就绪：公开页面不发布该照片，或显示明确占位而不是损坏图片。
- 浏览计数失败：静默降级，不影响灯箱。
- 数据库备份失败：写入日志并在后台概览显示告警。
- 自动首页封面来源失效：回退到上一次有效封面。
- CDN 故障：可临时回源展示图对象域名，原图仍保持私有。

## 12. 部署与运维

ECS 使用 Docker Compose 运行：

- `caddy`：TLS 与反向代理
- `app`：Nuxt 服务与后台任务执行器

SQLite、日志和临时工作目录使用持久卷。部署过程先完成数据库备份，再执行迁移和滚动重启。健康检查至少覆盖应用、数据库可读写和 OSS 凭据状态。

需要监控：

- 应用存活与响应时间
- ECS CPU、内存、磁盘
- API 5xx 和登录失败率
- 图片任务积压与失败
- OSS/CDN 流量与费用告警
- 最近一次数据库备份时间

## 13. 验收标准

### 公开端

- 桌面和移动端均能完成首页、摄影集、灯箱、记录详情和关于页浏览。
- 三种主题模式正确工作并记忆选择。
- 分类筛选可分享、刷新后状态不丢失。
- 灯箱支持键盘、触摸和浏览器返回。
- EXIF 不包含 GPS、序列号等敏感字段。
- 瀑布流不加载原图，布局没有明显跳动。

### 后台

- 管理员可以批量直传多张照片。
- 可看到上传与处理状态，并能重试单张失败任务。
- 可拖拽排序、指定封面、保存草稿、预览、发布和撤回。
- 两种首页封面模式均可切换并正确回退。
- 未登录用户不能访问管理 API。

### 数据与运维

- 同一访客对同一照片 24 小时内只计一次。
- 原图无法通过公开站点或 CDN URL 直接访问。
- SQLite 备份可以完成一次实际恢复演练。
- 在 2 核 2G ECS 上，批量上传与公开看图不会使应用因大图处理而耗尽内存。

## 14. 原型处置

`prototype-photo-journal/` 只用于验证视觉结构与交互方向。生产实现可以参考其内容、比例和动效感受，但不复制其临时代码、模拟数据或前端计数逻辑。
